### Owner selection and confirmation

The owner-only native dialog lists only ACTIVE, valid-handle, non-owner rows (also excluding the known owner handle). It reuses authorized avatar data and plain text names/handles; no new member read, visibility gate or permission. Checkboxes update the selected count in place; empty selection disables Remove Now. Remove Now shows a separate confirmation with the chosen handles and explicit Confirm Removal. Cancel on confirmation returns to selection; Escape/Cancel on selection closes without writes and restores the opener's focus.

Confirm Removal revalidates current client role/eligible rows, then calls the existing removeCrewMember / remove_crew_member RPC sequentially. Every request remains server-authorized. It stops at the first failure, refreshes Crews/members/Wall, reports the successful count and error, and keeps valid unremoved selections for retry. Successful handles are removed from the selection, so retry does not repeat them. This is not an atomic batch, and permission/network failures cannot be represented as full success. Refresh prunes stale/owner selections and closes the modal on loss of ownership.

A stable Crew content wrapper allows the native dialog to remain mounted while the surrounding original controls rerender or the dialog changes confirmation state. Keyboard Tab/Shift+Tab stay inside; disabled busy state prevents duplicate actions. The existing Desktop editor moves panels at 1024px: crossing that breakpoint safely dismisses the selection dialog without writes instead of leaving a disconnected non-modal dialog. Modal resize listeners are removed when it closes. Original Crew Wall editing/stages/publication actions and existing Delete/Leave confirmations remain.

Existing approved game-artwork data decorates the identity and Wall preview within the original owner management; safe provider allowlists/gradient fallbacks remain. No new media service or backend/storage change. Unrelated account.css, public files, mobile sections and accepted limits are untouched.

Desktop rows have at most three cards, each at most 19rem wide and with original 16:9 proportions; flex wrapping centers incomplete rows without stretching. Nine yields 3+3+3.
